## B. 附录 B「鸿蒙端实现要点」整段替换

| 条目 | 原型原文 | 修订后 |
|---|---|---|
| 页面路由 | @ohos.router 或 Navigation 栈 | `Navigation` 栈（主 Tab 由 `Tabs` 承载），不用 @ohos.router |
| 状态管理 | （原稿无） | **全站 `@ComponentV2` + 状态管理 V2**：`@ObservedV2/@Trace` ViewModel、`@Local`、`@Param/@Once`、`@Event`、`@Provider/@Consumer`、`@Monitor`、`@Computed`；禁止 V1 装饰器与 V1/V2 混用 |
| 数据持久化 | RelationalStore 关系库：users、goals、tasks、point_logs、review_notes，数据仅存本机 | **服务端 MySQL 8 为唯一数据源**（5 表）；`@ohos.data.relationalStore` 作本地缓存 / 离线镜像（同名同构），`@ohos.data.preferences` 存登录态与偏好；缓存不得参与业务判定 |
| 进度重算 | tasks 持 goalId 外键；进度 = 已完成任务数 / 关联任务总数，保存任务后触发 S3/S4/S7 重算 | 公式不变，改由 `ServiceImpl` 重算并回写 MySQL；客户端经 `GET /sync?since=` 或保存响应回刷缓存后刷新 S3/S4/S7 |
| 积分结算 | 任务完成事件累加积分并写流水；连续打卡按自然日，满 7 天 +50 | 由 `ServiceImpl` 结算并写 `point_logs`，客户端只展示服务端返回值；自然日判定在服务端 |
| 备份导出 | 应用沙箱文件 + 用户选择导出路径；数据仅存本机 | `GET /api/export` 由服务端生成备份，客户端保存到用户选择路径；数据源为 MySQL |
| 提醒服务 | @ohos.reminderAgentManager 后台代理提醒 | 保持不变（任务到期 + 每日 19:00 打卡） |
| 实现范围约定 | 积分体系只做「规则表 + 累计 + 展示」 | 保持不变 |

## C. 附录 A 交互流程

跳转结构不改。仅将「未登录 → S1 ──登录成功──→ S2 今日」中的「登录成功」注明为「服务端校验通过并下发会话态」，其余原样。

## D. 交付校验

逐项核对：所有页面不再出现「仅存本机 / 不上传云端 / 本地账号 / 本地校验」字样；登录确实发起 HTTP；积分与进度取自服务端响应；RelationalStore 内数据可由服务端重建；全站 `@ComponentV2` 无 V1 装饰器。
